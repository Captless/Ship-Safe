# V1.4 — Beginner-First Scan Report Redesign

## Objective

Redesign the Ship Safe scan results experience so it feels more useful,
alive, understandable, and actionable for beginner vibe coders.

The current scanner produces useful findings, but the report still feels
too technical and fragmented.

V1.4 should answer the user's main questions immediately:

1. Is my project ready to ship?
2. What should I fix first?
3. Why does it matter?
4. Can I give my coding AI one prompt to fix everything?
5. Where exactly is the problem if I want more technical detail?

The report should therefore use a beginner-first hierarchy while keeping
the existing technical information available through expandable details.

This is primarily a report UX/presentation redesign.

Do NOT change scanner detection, scoring, severity logic, or result
semantics unless the codebase inspection identifies a concrete issue
required by this implementation.

# 7. PRIORITY SUMMARY

Replace the feeling of a long error list with a simple priority summary.

Example:

    🔴 1  Fix before shipping
    🟠 2  Worth reviewing
    🔵 1  Good to know

# 8. YOUR NEXT STEP

Provide a clear action based on the highest-priority findings.

Example:

    YOUR NEXT STEP

    Fix the critical issue first.
    The remaining items can be reviewed afterward.

    [ Fix these with AI ]

For a clean project:

    YOUR NEXT STEP

    Continue with your normal testing and deployment review.

Do not claim that Ship Safe guarantees security.

---

# 9. CONSOLIDATED AI FIX PROMPT

Replace the primary UX of separate AI prompts with ONE consolidated
AI Fix Prompt.

Preferred UI:

    FIX THESE ISSUES WITH AI

    Ship Safe found 3 issues worth fixing before launch.

    We've combined the relevant findings into one prompt you can
    paste into your AI coding assistant.

    [ Copy AI Fix Prompt ]

Optional:

    [ Show prompt ]

The user should not need to copy three or five separate prompts.

---

# 10. CONSOLIDATED PROMPT CONTENT

The consolidated prompt should contain all actionable findings.

For each finding include, where available:

- severity
- title
- beginner explanation
- why it matters
- affected file/location
- recommended action
- sanitized technical context

The prompt should instruct the coding assistant to:

1. Inspect the existing project first.
2. Understand the existing architecture.
3. Address the listed findings.
4. Make the smallest appropriate changes.
5. Avoid creating duplicate files.
6. Preserve existing behavior.
7. Avoid unrelated refactoring.
8. Verify the changes.
9. Summarize what changed.

Do not tell the AI coding assistant to blindly rewrite the project.

---

# 11. AI PROMPT SECURITY

The consolidated prompt MUST preserve existing redaction.

Never include raw:

- API keys
- passwords
- tokens
- private keys
- credentials
- secrets

in the generated prompt.

Use sanitized context instead.

If the existing individual prompt generation already performs
sanitization, reuse it.

Do not create a second incompatible sanitization implementation.
